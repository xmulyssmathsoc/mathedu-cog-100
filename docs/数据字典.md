# MathEdu-Cog 100：数据字典与标注含义

## 一、数据库设计

采用双层结构：规范化 SQLite 关系表负责检索、外键和统计；`all_records.doc` / `canonical_records.jsonl` 保留完整的 13 类 JSON 实体。底层关联通过稳定 `id` / `item_id` / `concept_id` / `family_id` 连接。

| 概念对象 | SQLite 表 | 关键属性 | 规模 |
|---|---|---|---:|
| 数据来源 | provenance | origin_type、generator_model、validation_level | 1 |
| 数学概念 | concepts | label、definition、prerequisite_ids | 80 |
| 知识前置关系 | concept_edges | from_concept、to_concept、relation | 29 |
| 数学题目 | questions | stem、correct_answer、stage、difficulty、split | 100 |
| 题目概念关系 | item_concepts | item_id、concept_id、role | 100 |
| 数学解法 | solutions | methods.steps、mathematical_validity_check | 100 |
| 候选错误模式 | error_patterns | signature、wrong_answer_examples、category | 200 |
| 认知假设 | cognitive_hypotheses | kind、evidence_level、alternatives | 400 |
| 诊断问题 | diagnostic_probes | stem、correct_answer、predicted_responses | 200 |
| 合成学生作答 | student_observations | raw_response、correctness、source_type | 400 |
| 认知状态推断 | cognitive_inferences | observations、hypotheses、certainty | 200 |
| 教学干预 | teaching_interventions | action、learner_facing_message、followup_probe | 100 |
| 模拟教学会话 | teaching_sessions | turns、completion_reason、source_type | 100 |
| 学习效果占位 | learning_outcomes | independent_assessment、causal_attribution、score | 100 |
| 教学行动偏好 | teaching_preferences | candidate_a、candidate_b、choice、rating_rubric | 100 |
| 全量 JSON 文档 | all_records | record_type、provenance_id、doc | 2081 |

## 二、误区与认知判断的逻辑

1. `error_pattern.observed_signature`：表面上能够看到的具体错误行为。它本身不代表心理原因已被确认。
2. `cognitive_hypothesis.kind`：理论候选机制，分为 `concept_misconception`（概念误解）、`pseudo_understanding`（可能的伪理解）、`insufficient_evidence`（证据不足）等。
3. `positive_evidence` 与 `counter_evidence`：支持或削弱假设的观测条件；当前为理论上的诊断规则，不是从真人数据估计的概率。
4. `diagnostic_probe.hypotheses_to_distinguish`：该追问希望区分的假设 ID；`information_value_basis=model_estimate`，非实际区分度。
5. `cognitive_inference`：只记录当前证据范围内的可能解释。`confidence_score` 属于未校准的模型分数，并非概率预测。
6. `teaching_preference`：在模拟场景中的教学行为比较，评价的是规范性教学质量，不是独立实验支持的学习成效。

## 三、八类伪理解风险

| 代码 | 名称 | 识别方向 |
|---|---|---|
| `rote_recall` | 结论记忆 | 记住结果却不理解原理 |
| `template_matching` | 套路匹配 | 借助固定流程处理熟悉题型 |
| `surface_pattern` | 表面特征依赖 | 根据符号、图像外观或关键词判断 |
| `false_generalization` | 过度概括 | 将特殊条件误当成一般规律 |
| `fragile_transfer` | 迁移脆弱 | 稍换形式或边界条件便失效 |
| `unjustified_fluency` | 流畅表达但无依据 | 能说术语，缺乏必要论证 |
| `hindsight_illusion` | 事后理解错觉 | 看过讲解后觉得会了，但独立变式仍困难 |
| `answer_only` | 仅结论证据不足 | 作答结果正确，推理证据缺乏 |

以上是**候选风险分类**，不能据此直接诊断真实学生。

## 四、题目 ID 与拆分

- 题目编码如 `CAL-003`：`CAL` 表微积分领域，`003` 是该领域题号。
- `C-CAL-xxx` 表示数学知识概念节点。
- `E-CAL-003-1` 表示该题的第一种可观察错误模式。
- `H-CAL-003-PU` 表示伪理解风险，`H-CAL-003-UNK` 表示证据不足。
- `P-CAL-003-1` 和 `P-CAL-003-2` 是两条诊断题。
- `O-CAL-003-C / -E1 / -E2 / -PU` 分别表示完整正确、错误1、错误2、结论正确但论证不足的合成回答。
- `I-*` 表认知推断，`T-*` 表教学提示，`SE-*` 表会话，`LO-*` 表未评测后测占位，`PR-*` 表偏好比较。
- `split` 分为 `train`（70 题）、`validation`（15 题）、`synthetic_test`（15 题）。

## 五、查询示例

```sql
-- 中学代数题及难度
SELECT id, difficulty, stem FROM questions
WHERE domain_code='ALG' AND stage='middle_school';

-- 某道题的错误表现
SELECT observed_signature, json_extract(doc,'$.wrong_answer_examples[0]') AS wrong_response
FROM error_patterns WHERE item_id='CAL-003';

-- 查找伪理解风险类型
SELECT id, json_extract(doc,'$.pseudo_understanding_subtype') AS subtype, label
FROM cognitive_hypotheses WHERE kind='pseudo_understanding';

-- 题目诊断路径
SELECT stem, correct_answer
FROM diagnostic_probes WHERE item_id='CAL-003' ORDER BY id;

-- 验证没有伪造独立后测
SELECT COUNT(*) FROM learning_outcomes WHERE independent_assessment=1;
-- 期望结果：0
```

## 六、扩容注意

- 追加真实学生数据时必须新建 `provenance` 记录，并进行隐私审查和真实数据授权；不可直接覆盖合成记录。
- 来自不同弱模型的模拟回答应记录真实的模型 ID、提示参数和生成版本；本版本没有运行早期弱模型。
- 要建立研究可用的正式评测集，必须引入独立真实数据和专家评估；`synthetic_test` 仅用于内部功能检查。
- 标准解答目前保存在题目和 solution 记录中；导出教师训练上下文时，未来尚未公开的标准答案不能出现在学生可见消息内。
