# 30 道错误案例：数据字段说明

这是 MathEdu-Cog 100 v1.1 的**补充实体**，保留原版 13 类记录及原 JSON Schema，不破坏既有训练管线。

| JSON 字段 | 内容 | 标注规则 |
|---|---|---|
| `case_id` | EC-001 至 EC-030 | 全局唯一 |
| `item_id` / `item_family_id` | 关联到原 100 题 | 派生案例沿用母题 train / validation / synthetic_test 划分 |
| `problem` / `reference_answer` | 题干及原题参考答案 | 从数据库原题读取，避免重复人工复制 |
| `simulated_student_response` | 逐步模拟错误解答与错误结论 | **模拟文本**，非真实学生作答 |
| `first_invalid_step` | 首处明确不合法的步骤 | 应可从数学推导本身解释 |
| `observed_error` | 错误为什么在数学上不成立 | 描述可观察错误或规则误用，不直接给人格或能力标签 |
| `candidate_cognitive_explanations` | 候选理解误区、其他解释、反向证据 | **假设**，不能仅据一道题确诊 |
| `diagnosis` | 区分性追问与两类可能回答 | 预测答案，不是实测频率 |
| `correction` | 正确的分步解法与结论 | 标注数学审定仍需独立复核 |
| `teaching_intervention` | 最小提示及引导策略 | 不应只靠直接给答案 |
| `transfer_check` | 独立变式题与解析 | `not_administered`，没有声称学生已掌握 |
| `pseudo_understanding_check` | 学生复述原结论但未能独立迁移的风险 | 风险提示，尚未验证 |
| `provenance` | 生成来源、模型与审核情况 | 明确无真人学生、未调用早期弱模型、无独立教师复核 |
| `evidence_level` / `approval` | 标注证据等级及状态 | `synthetic_theoretical_candidate` / `pending_independent_review` |

**注意**：旧的 `data/canonical_records.jsonl` 仍有 2081 条，旧验证脚本按此数量校验；30 道案例在 `data/error_cases_30.jsonl` 与 SQLite `error_cases` 表中，附带一条新的来源元数据。逻辑内容记录数量为 2111，来源元数据在扩展中单独保存。

建议仅使用 `exports/train/` 下的文件进行模型训练；保留其它两个划分用于合成数据检查。它们不能替代真实学生上的评测。
